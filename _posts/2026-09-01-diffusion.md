## [](#prologue)Prologue
Images generated by machine learning models up until the end 2010s were not very impressive compared to today's standards. When diffusion models were introduced and had matured for some years, they really took off. The diffusion model architecture had more stable training, and also enabled some significant tweaks. Today, diffusion models are used to create ultra-realistic images and videos, albeit GANs are much faster at inference, and therefore still viable in that sense. This post will cover how they work, and show an example of a simple version for creating custom Pokémon sprites.

Conceptually, what is generative model? This would be a model that maps any input to a *distribution* of possible outputs: $$ f(x,\theta)=y+\epsilon$$. For image-to-image generation, the input is an image, and the output is a *sample* image from a distribution of images. When generating from scratch, the input would be some kind of noise or *seed*. You might even introduce text-conditioning, which guides the generation based on the text input prompt. The stochastic part of the output, $$\epsilon$$ (often indicating something random), comes from the fact that the generative process of image, text, audio, etc. is inherently based on random processes. But why is that?

Imagine the case where one prompt (input) always gave the same output; How would we define which mappings are the best ones? Using the prompt "dog" to generate an image of a dog, gazilion images would satisfy the condition of being an image of a dog.

P(A)   : what is the distribution of all thinkable images (intractable to compute)
P(B)   : how latent is distributed (we can enforce a distribution)
P(A|B) : given a certain latent, how *likely* is the data to occur
P(B|A) : given our training data, how do we shape the output distribution (the goal of training)

"latent" meaning manifold of output image
"data"   meaning actual image (in practice, the training data)
